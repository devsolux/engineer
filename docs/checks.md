# Checks and evidence

`make lint` parses every canonical Python/Bash/JSON/SVG source and validates core
local links and marketplace identity. `make validate` runs the module, command,
supply-chain, script, reference-budget, and fixture-hash checks.
`make evals` checks the full scenario bank structure without calling a model.
`make verify-build` compares generated bytes and modes against canonical source.

`make test` discovers every `scripts/test-*.sh` and `scripts/test-*.py`. Each suite
runs in an isolated copy of the source. Logs and a machine-readable summary go to
`.build/tests/`. An unknown selection, missing prerequisite, nonzero exit, or
timeout cannot count as passing. Set `JOBS` for parallel isolated suites.

```bash
python3 scripts/run-tests.py --list
python3 scripts/run-tests.py --select test-plugin-build.py
```

Tests exercise synthetic positive and negative cases. Some test fake host binaries
and temporary Git workspaces; those are not real host or marketplace acceptance.
TypeScript template tests use controlled API stubs. No authenticated live model
runs, browser session, GitHub action execution, deployment, or publishing is
implicit in these targets.

`make fixtures` is a maintenance write, not a verification shortcut. Review why
hashes changed, retain illustrative markers, rebind, then rerun all affected tests.
Never use it to re-sign unreviewed or externally captured evidence. The
completion sample is also illustrative and its content hashes must match its
actual checked-in source documents.
