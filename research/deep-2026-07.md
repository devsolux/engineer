# 1. Design & tokens

### Findings (2026)

- Tailwind **v4** is CSS-first: `@theme` / `@theme inline` replace JS config for tokens.
- Default palette ships **OKLCH**; custom brand colors should use `oklch()` for even scales.
- Two-layer model remains best: `:root` semantic vars → `@theme inline` maps to utilities.
- Namespace prefixes (`--color-*`, `--font-*`, `--radius-*`) are load-bearing for utility generation.
- shadcn: theme in `globals.css`; **wrapper pattern** — never edit `components/ui/*` for product API.

### Encoded in skill

- `design-system.md` OKLCH + semantic tokens  
- Enforcement greps for hardcoded palette  

### Gaps / deepen next

| Gap | Severity | Action |
|---|---|---|
| No motion-token module (duration/easing system beyond a11y reduced-motion) | Low | Fold into design-system if 3+ projects need |
| No density modes (compact/comfortable) | Low | design-patterns when dashboard density ships often |
| Container queries / `@utility` recipes thin | Medium | Expand design-patterns or stack-rules |

### Rules to keep binding

- Semantic tokens only in product UI  
- WCAG 2.2 AA contrast on semantic pairs  
- 8pt grid; 44px targets

# 3. Frontend architecture (RSC, state, streaming, perf)

### Findings

- RSC default; client islands at leaves; serializable props only.
- Next 16: **dynamic by default**; `use cache` opt-in; PPR with `cacheComponents`.
- Invalidation split: `updateTag` (Actions, read-your-writes) vs `revalidateTag` (handlers, SWR-style).
- State order: URL → Server/RSC → server cache/query → Zustand **UI chrome only**.
- CWV field targets: LCP ≤2.5s, INP ≤200ms, CLS ≤0.1 (CrUX).
- Compose vercel `react-best-practices` for granular React rules.

# 4. Frontend testing (Playwright deepen)

### Findings (2026 practice)

- Pyramid: Vitest unit → RTL integration → Playwright 5–15 critical flows.
- **Auth setup project**: log in once → `storageState` → dependent projects for authenticated suites.

# 7. Server Actions, APIs, rate limits

### Findings

- Treat every action as public HTTP; five gates (auth, authz, Zod, rate limit, safe errors).

- Order: auth → rate limit → validate → mutate.

# 8. Background jobs & queues — **major miss**

### Findings (2026 landscape)

| Tool | Architecture | Best when |
|---|---|---|
| **Inngest** | Event-driven workflows, serverless-native | Vercel, multi-step retries, fan-out |
| **Trigger.dev** v3 | Managed task runners, strong DX/debug | Long tasks, self-host option, AI jobs |
| **BullMQ** + Redis | Self-operated queues | Own servers/VPS, cost control |
| **pg-boss** | Postgres-backed jobs | Already on Supabase/Postgres, simple |
| **Vercel Cron** | Scheduled HTTP only | Minute-level schedules, not workflows |

**Consensus**: on Vercel, do **not** pretend long work fits in a Server Action. Webhooks should enqueue; email, PDF, AI, dunning, GDPR delete should be jobs.

### Encoded in skill today

- Mentions only: architecture scaling table, rust “when jobs”, compliance “idempotent job queue”, api-data-flows event-driven row.

# 11. Growth, conversion, onboarding (PLG 2026)

- Activation is the battleground: 40–60% of free users never activate (zombie users).
